# RADAR 0.1 Implementation Plan (radar crate)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `radar` crate 0.1. It is a deterministic, realism-first radar simulation library with scanning, range-equation detection, noise, false alarms, occlusion, tracking, identification and noise jamming.

**Architecture:** A single crate with feature-gated modules. The host supplies `WorldSnapshot`s and advances a `Simulation` clock. Each sensor is configured by plain-data enums (with `Custom(Box<dyn Trait>)` escape hatches) and owns its runtime state and its own seeded random stream. Outputs are `Observation`s that never carry ground truth.

**Tech Stack:** Rust 2024 (MSRV 1.85), `rand_core` 0.10, `rand_chacha` 0.10, `thiserror` 2; optional `serde` 1 and `getrandom` 0.4. Dev: `proptest` 1, `approx` 0.5, `criterion` 0.8.

**Spec:** `docs/superpowers/specs/2026-11-17-radar-0.1-design.md`. Read it alongside this plan; section numbers below (§) refer to it.

**Companion plan:** `docs/superpowers/plans/2026-11-17-robocode-radar-integration.md` (robocode repo work; it starts after Task 10 of this plan).

## Global Constraints

- Licence `AGPL-3.0-only`, edition `2024`, `rust-version = "1.85"` (already set in `Cargo.toml`).
- Runtime dependencies are limited to: `rand_core = "0.10"`, `rand_chacha = "0.10"`, `thiserror = "2"`, optional `serde = { version = "1", features = ["derive"] }`, optional `getrandom = "0.4"`. No `glam`, `nalgebra`, `rand`, or `rand_distr`.
- Features: `default = ["tracking", "ew"]`; `tracking = []`, `ew = []`, `serde = ["dep:serde"]`, `entropy = ["dep:getrandom"]`, `diagnostics = []`.
- All internal quantities are SI and radians. World frame: x = east, y = north, z = up. Azimuth is a compass bearing (from +y, clockwise, `[0, 2π)`). Elevation is measured up from horizontal (`[-π/2, π/2]`).
- No public observation type (`Measurement`, `Track`, `Observation`) may contain a `TargetId`.
- No panics on user input. Validation returns `RadarError`.
- Determinism: draws happen per sensor in a fixed order: targets in ascending `TargetId` order, then false alarms, then identification replies, then tracking. Samplers are implemented in-crate.
- `cargo fmt --check`, `cargo clippy --all-features --all-targets -- -D warnings`, and `cargo test --all-features` must pass at every commit. Every public item gets rustdoc (`#![warn(missing_docs)]` in `lib.rs`).
- rand_core 0.10 names the generator trait `rand_core::Rng` (not `RngCore`). `ChaCha8Rng::seed_from_u64` and `set_stream(u64)` are verified to exist.

## Review Focus

1. **A sensor whose platform is missing from the snapshot** (e.g. the carrier was destroyed). Expected: the sensor skips its update silently and produces no observations, with no error and no panic. The test is in Task 10.
2. **Targets at zero or near-zero range from the sensor** (co-located, or inside `extent_radius`). Expected: no NaN, no division by zero; the target is treated as overlapping the beam (half-extent π) and is still subject to `min_range`. The test is in Task 7.
3. **Azimuth sweeps across north (359° → 1°) and negative steering commands.** Expected: the swept arc wraps correctly and targets at 0° are illuminated. The test is in Task 7.
4. **`update_world` with a snapshot older than the previous one, or `step` with zero duration.** Expected: an older snapshot returns `RadarError::TimeWentBackwards`; `step(0)` is a no-op that returns `Ok`. The test is in Task 10.
5. **Adding or removing a sensor mid-run must not change other sensors' random streams**, and `reset()` must reproduce the run from time zero exactly. The test is in Task 16 (Scenario C and determinism).

### Task 6: Radar configuration, antenna, calibration

**Files:**
- Create: `src/radar/{mod,config,antenna,calibration}.rs`

**Interfaces:**
- Produces:
  - `pub enum Dimension { TwoD, ThreeD }`; `pub enum BeamPattern { Gaussian, Uniform }`; `pub enum ScanFrame { PlatformRelative, WorldStabilised }` (default `PlatformRelative`).
  - `AntennaConfig { beamwidth_az: f64, beamwidth_el: f64, pattern: BeamPattern, sidelobe_level_db: f64 /* default -30 */ }` with `gain(&self, off_az: f64, off_el: f64, dim: Dimension) -> f64`. This is the normalised two-way-ready one-way power gain in `[sidelobe, 1]`. Gaussian: `exp(-4 ln2 ((off_az/bw_az)² + (off_el/bw_el)²))` (2D drops the el term). Uniform: 1 when inside both half-beamwidths, else sidelobe. Result is `max(main, db_to_linear(sidelobe_level_db))`.
  - `pub enum Calibration { Physical { peak_power_w, gain_db, frequency_hz, noise_figure_db, bandwidth_hz, losses_db }, Reference { rcs_m2, range_m, snr_db } }` with:
    - `snr_constant(&self) -> f64`. K is such that `SNR = K·σ·g²/R⁴`. Physical: `Pt·G²·λ²/((4π)³·k·T0·F·B·L)`. Reference: `db_to_linear(snr_db)·range_m⁴/rcs_m2`.
    - `jnr_constant(&self) -> Option<f64>`. J/N per unit ERP at 1 m with g = 1: Physical gives `G·λ²/((4π)²·k·T0·F·B)`; Reference gives `None`.
